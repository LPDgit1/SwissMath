## Incomplete or inconsistent state

- Core and Desktop metadata still say `0.5.0`; Web metadata still says `0.1.0`, while the interrupted HTML labels itself Web v0.2 / Core v0.6.
- No v0.6 integration/reference tests or focused v0.6 benchmarks exist.
- `README.md`, `CHANGELOG.md`, and `BENCHMARKS.md` do not document v0.6.
- The Web adapter exposes only a subset of the intended v0.6 primitives. It has partial calls for xgcd, next-prime, Mobius/divisor summary, and reconstruction; valuation, radical, squarefree, previous-prime, and distinct bounded reconstruction are absent.
- The interrupted Web frontend is a broad six-category redesign and has not been production-built or browser-smoke-tested in its present form.
- The new `arithmetic.rs` and `fractions.rs` contain additional general-purpose features outside the recovered v0.6 release scope. `discovery.rs`, `linear_algebra.rs`, and `polynomials.rs` anticipate later releases. They are preserved, but are not evidence that v0.6 is complete.
- No source-level `TODO`, `FIXME`, `todo!`, or `unimplemented!` marker was found. Incompleteness is architectural/API-level rather than marked in code.
- No obvious duplicated factorization was found in the current Core implementation, but `IntegerAnalysis` does not yet carry the new factorization-derived v0.6 scalar results.

## Recovery conclusion

The worktree compiles and its existing tests pass, but Core v0.6 is incomplete.
Completion should preserve the valid factorization and primality architecture,
repair only the APIs above, add independent reference tests and focused
benchmarks, and keep divisor enumeration explicitly opt-in.
